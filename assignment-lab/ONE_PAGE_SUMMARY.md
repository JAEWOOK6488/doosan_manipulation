# IC-PBL 1쪽 요약

## 과제 질문

박스를 집고 놓을 때 실제 하중은 수십 ms에 걸쳐 작업대와 로봇 사이를 오간다.
그런데 기준 제어기·관측기는 `grip` 신호 순간에 빈손/완전 하중 모델을 계단
전환한다. 이 차이 때문에 토크가 튀고 박스가 작업대를 누르며, 정상 하중 전달을
충돌로 오인한다. 목표는 6초 택트와 1 kHz 주기를 유지하면서 두 문제를 함께
줄이는 것이다.

## 제안안

1. **연속 하중 스케줄**: 빈손과 완전 하중 역동역학을 25 ms smoothstep
   하중률로 보간한다. 놓기에서는 질량에 따라 접촉 예상시각을 앞당긴다.
2. **1.25 mm 미세 호버**: release 전 TCP를 조금 들어 작업대 누름을 줄인다.
3. **상태별 혼합 운동량 관측기**: 정상 구간에는 전체 잔차, 하중 천이에는
   알려진 페이로드 토크 방향의 예상 응답만 제거한 잔차를 쓴다.
4. **교정 보호**: 기동 50 ms 뒤부터 5 ms 변화를 감시해 충돌을 영점 교정값으로
   학습하지 않는다.
5. **Cartesian 보조 판정**: 안정·저잡음 구간에 `tau_ext=J_v^T f`로 힘 잔차를
   복원해 자세에 따라 관절 잔차가 작아지는 사각을 메운다.

## 쓸 수 있는 데이터

- 직접 입력: 모터측 `th`, 1 ms 차분 `thd`, JTS `tau_s`, grip, 목표 궤적
- 감지기 추가 입력: 직전 주기 적용 모터토크 상당값 `tau_m`
- 알려진 모델: 빈손/박스 포함 `M`, `h`, `g`, TCP `J`, 질량·COM
- 직접 불가: 링크각 `q`, 실제 충돌력, 작업대 힘, 무잡음 실제 토크

“앞뒤 두 개”는 전류 두 개가 아니라 모터측·출력측 엔코더다. 현재 공식
콜백에는 출력측 `q`가 없어서 최종안은 `q≈th-tau_s/K`로 복원한다.

## 한계

- 10 N은 자세·방향에 따라 미검출된다.
- 고정 1.25 mm 호버는 작업대가 +2 mm 이상 높을 때 정상 접촉 경보가 날 수 있다.
- 질량·COM을 정확히 안다고 가정한다.
- 질량·COM을 숨긴 1,000회 별도 감사에서는 충돌 구분 51.5%, 무충돌 조건
  경보 9.0%였다. 따라서 94.1% 결과는 payload가 설정된 조건으로만 해석한다.
- 동일한 미지 조건의 비교에서는 1차 기준안 34.6% → 2차 51.5%(+16.9%p),
  무충돌 경보 조건 245 → 90건이었다.
- CPU 최대는 200.2/206.7 μs지만 벽시계 단발 정지는 1.24/3.25 ms였다.
- 실제 M1013의 JTS 영점·마찰·패드 압축·작업대 높이로 다시 튜닝해야 한다.
